Polling has two problems: most requests return nothing, and a new message
arrives up to one polling interval late. With WebSockets, the server pushes a
message to all clients the moment it arrives.

## WebSocket Basics

[WebSocket](https://en.wikipedia.org/wiki/WebSocket) is a two-way communication protocol.
The connection starts as a normal HTTP request with an `Upgrade: websocket`
header. If the server agrees, the same TCP connection stays open, and both
sides can send messages at any time.

[WebSocket](https://en.wikipedia.org/wiki/WebSocket) is fully usable since 2011,
when the protocol was standardized as [RFC 6455](https://datatracker.ietf.org/doc/html/rfc6455).
You can use [WebSocket on all modern browsers](https://caniuse.com/websockets).
The JavaScript API is part of the
[WHATWG HTML standard](https://html.spec.whatwg.org/multipage/web-sockets.html).

## The Server

This part uses [Flask-SocketIO](https://flask-socketio.readthedocs.io/). It speaks the
Socket.IO protocol, which runs on top of WebSockets and adds automatic
reconnects, rooms and a fallback to long polling. The price: the client needs
the Socket.IO library, a plain `WebSocket` object can't talk to it. If you want
plain WebSockets, [flask-sock](https://github.com/miguelgrinberg/flask-sock) is
the smaller alternative.

```text
pip install flask flask-socketio
```

`app.py`:

```python
from flask import Flask, render_template
from flask_socketio import SocketIO, emit

app = Flask(__name__)
app.config["SECRET_KEY"] = "change-me"
socketio = SocketIO(app)


@app.route("/")
def index():
    return render_template("index.html")


@socketio.on("send_message")
def handle_message(data):
    text = str(data.get("text", "")).strip()[:2000]
    if text:
        emit("new_message", {"text": text}, broadcast=True)


if __name__ == "__main__":
    socketio.run(app, debug=True)
```

The server doesn't poll and doesn't loop: when a client sends a
`send_message` event, the handler broadcasts a `new_message` event to all
connected clients, including the sender. In the real application, this is also
the place to store the message in the database, as in part I.

## The Client

`templates/index.html`:

```html
<!DOCTYPE html>
<html>
  <head>
    <meta charset="utf-8">
    <title>Flask Chat</title>
  </head>
  <body>
    <ul id="messages"></ul>
    <form id="form">
      <input id="input" autocomplete="off">
      <button>Send</button>
    </form>

    <script src="https://cdn.socket.io/4.7.5/socket.io.min.js"></script>
    <script>
      const socket = io();
      const form = document.getElementById("form");
      const input = document.getElementById("input");

      form.addEventListener("submit", (event) => {
        event.preventDefault();
        if (input.value) {
          socket.emit("send_message", {text: input.value});
          input.value = "";
        }
      });

      socket.on("new_message", (message) => {
        const item = document.createElement("li");
        item.textContent = message.text;
        document.getElementById("messages").appendChild(item);
      });
    </script>
  </body>
</html>
```

Note `textContent` instead of `innerHTML`: messages from other users must never
be interpreted as HTML, otherwise everybody can run JavaScript in the browsers of
all other users ([cross-site scripting](../xss/)).

Start it with `python app.py` and open `http://localhost:5000` in two browser
windows: a message from one appears instantly in the other.

## Testing

Flask-SocketIO has a test client, so the event handlers can be tested without a
browser:

```python
from app import app, socketio


def test_message_is_broadcast():
    alice = socketio.test_client(app)
    bob = socketio.test_client(app)
    alice.emit("send_message", {"text": " hi "})
    received = bob.get_received()
    assert received[0]["name"] == "new_message"
    assert received[0]["args"][0] == {"text": "hi"}
```

## Scaling

The often-quoted limit of $2^{16} = 65536$ connections per IP address is a
misunderstanding: it applies to the outgoing ports of one client IP. A
connection is identified by client IP, client port, server IP and server port,
so a server can hold far more connections on a single port. The real limits are
open file descriptors (`ulimit -n`) and memory. You might want to limit the
number of connections your app accepts. Otherwise, it could happen that you
can't ssh into your server anymore.

As soon as you run more than one server process, two problems appear:

1. A broadcast from one process only reaches the clients connected to that
   process. Flask-SocketIO solves this with a message queue:
   `SocketIO(app, message_queue="redis://")`. All processes publish to Redis
   and deliver what they receive to their own clients.
2. The load balancer has to send all requests of one Socket.IO client to the
   same process ("sticky sessions"), at least while the long-polling fallback is
   in use.

For more details, see [^1],[^2],[^3].
