[Electron](https://en.wikipedia.org/wiki/Electron_(software_framework)) is a
framework that allows the development of GUI applications using the Chromium
rendering engine and the Node.js runtime. It should make packaging and shipping
for multiple platforms easy:

<iframe width="560" height="315" src="https://www.youtube-nocookie.com/embed/8YP_nOCO-4Q" frameborder="0" allow="accelerometer; autoplay; encrypted-media; gyroscope; picture-in-picture" allowfullscreen></iframe>

Many desktop applications you probably use are built with it: Visual Studio
Code, Slack, Discord and Obsidian, for example. The appeal is obvious: one code
base in HTML, CSS and JavaScript runs on Windows, macOS and Linux, and web
developers can build desktop apps without learning a new GUI toolkit.


## How it works

An Electron app has two kinds of processes
([docs](https://www.electronjs.org/docs/latest/tutorial/process-model)):

* The **main process** runs Node.js. It creates windows, talks to the operating
  system (menus, tray icon, notifications, file system) and controls the
  lifecycle of the app.
* Every window has a **renderer process**: a Chromium page that shows your
  HTML. For security reasons it has no direct access to Node.js.
* A **preload script** connects both: it runs before the page loads and can
  expose a small, explicit API to the page via `contextBridge`.


## Hello World

See the [official tutorial](https://www.electronjs.org/docs/latest/tutorial/tutorial-first-app).

What you need is pretty slim:

```text
.
├── index.html
├── LICENSE.md
├── main.js
├── package.json
├── package-lock.json
├── preload.js
├── README.md
└── renderer.js
```

Install Electron as a development dependency:

```text
npm init
npm install --save-dev electron
```

`package.json` needs the entry point and a start script:

```json
{
  "name": "hello-electron",
  "version": "1.0.0",
  "main": "main.js",
  "scripts": {
    "start": "electron ."
  }
}
```

`main.js` opens a window and loads the HTML file:

```javascript
const { app, BrowserWindow } = require('electron')

function createWindow () {
  const win = new BrowserWindow({ width: 800, height: 600 })
  win.loadFile('index.html')
}

app.whenReady().then(() => {
  createWindow()

  // macOS: re-create a window when the dock icon is clicked
  app.on('activate', () => {
    if (BrowserWindow.getAllWindows().length === 0) createWindow()
  })
})

// Quit when all windows are closed, except on macOS
app.on('window-all-closed', () => {
  if (process.platform !== 'darwin') app.quit()
})
```

`index.html` is a normal web page:

```html
<!DOCTYPE html>
<html>
  <head>
    <meta charset="UTF-8">
    <meta http-equiv="Content-Security-Policy" content="default-src 'self'">
    <title>Hello World</title>
  </head>
  <body>
    <h1>Hello World</h1>
  </body>
</html>
```

`npm start` opens the window.


## Packaging

To give the app to other people, you need an installer per operating system.
[Electron Forge](https://www.electronforge.io/) is the officially recommended
tool:

```text
npm install --save-dev @electron-forge/cli
npx electron-forge import
npm run make
```

The installers end up in `out/make/`. Like with most tools of this kind, you
build Windows installers on Windows and macOS packages on a Mac; a CI pipeline
with one job per operating system is the easiest way. For macOS and Windows you
also want to sign the app, otherwise users see scary warnings.


## Pros and cons

Pros:

* One code base for three operating systems.
* The whole web ecosystem: frameworks, UI libraries, developer tools.
* The page looks the same everywhere, because it always runs in the bundled
  Chromium.

Cons:

* **Size.** Every app ships its own copy of Chromium and Node.js. Even a "Hello
  World" is easily 100 MB and more.
* **Memory.** Each app is a browser of its own. Five Electron apps are five
  browsers.
* **Security** needs care: keep `contextIsolation` on and `nodeIntegration` off
  (both are the defaults now), load only local content and set a Content
  Security Policy.


## Alternatives

* [Tauri](https://tauri.app/) uses the web view of the operating system instead
  of bundling Chromium, and a Rust backend. The apps are much smaller.
* For Python, [Eel](../eel/) and [pywebview](https://pywebview.flowrl.com/)
  combine a Python backend with an HTML frontend.
